# Заглушки и что не реализовано

Честный список того, что временно или отсутствует. Всё остальное (БД, ИИ,
натальная карта, расклады) — рабочее.

## Оплата — мок

- `PayModal` (`src/components/PayModal.tsx`) при «Подтвердить» просто вызывает
  `onPay()` и пропускает пользователя дальше. Никакого платёжного провайдера.
- Точки, где всплывает оплата:
  - шаг расклада по платному продукту (`SpreadClient.tsx`);
  - «Полная матрица судьбы» (`MatrixClient.tsx`);
  - «День подробно» (`DayDeep.tsx`);
  - допродажа диалога с тарологом (`ChatUpsell` → `PayModal`).
- **Что сделать:** подключить провайдера (YooKassa / CloudPayments / Stripe),
  вебхук подтверждения, реальное списание с баланса aura.

## Баланс aura — заглушка

- Валюта `aura` (1 aura = 1 ₽) отображается в ценах и в шапке, но баланс везде
  захардкожен «0» (`SiteHeader`, `/profile`).
- Пакеты пополнения в профиле (`/profile`) — кнопки `disabled`.
- **Что сделать:** таблица баланса/транзакций, пополнение через платёжку,
  списание при покупке расклада, проверка «хватает ли aura» перед разбором.

## Авторизация — временная

- email + пароль (bcrypt), кука-сессия, таблица `sessions`. Токен хранится в БД
  открытым текстом.
- **Нет:** подтверждения почты, восстановления пароля, OAuth/соцсетей, 2FA,
  rate-limit на попытки входа, CSRF-токенов (полагаемся на `SameSite=lax`).
- Валидация пароля минимальная (≥ 8 символов).
- **Что сделать:** заменить целиком под нужный сценарий. Швы — комментарий в
  `src/lib/auth/index.ts`. См. [AUTH.md](./AUTH.md).

## История раскладов — только запись

- Расклады пишутся в `readings`, список показывается в `/profile`.
- **Нет:** страницы отдельного сохранённого расклада, повторного открытия,
  «продолжить диалог по старому раскладу», памяти прошлых раскладов в промпте
  (сейчас ИИ помнит только текущий расклад + натальную карту).

## Прочее

- **Число карт в продукте vs движке:** в `readings.ts` у продуктов свои числа
  (`cards: 6/7/9/12`), а реальное число задаёт движок (`three`=3, `relationship`=5,
  `celtic`=10). Согласовать или сделать отдельные движки под каждый продукт.
- **«Прогноз на месяц» / «Карьера»** используют движок `celtic` (позиции —
  «Ситуация/Вызов/…»), а не расклад, заточенный под месяц/карьеру. Можно завести
  отдельные `Spread` с подходящими позициями.
- **Картинки карт** — обводки колоды Райдера-Уэйта; для коммерческого запуска
  перепроверить статус и/или заменить. См. [DATA-SOURCES.md](./DATA-SOURCES.md).
- **«Матрица судьбы»** — метод свой, не канонический (Ладини). См. [DATA-SOURCES.md](./DATA-SOURCES.md).
- **Colбэк-эффект стрима** `[api/reading] Controller is already closed` в логах при
  обрыве соединения клиентом — ловится и логируется, безвреден.
- `luxon`, `tz-lookup` в зависимостях не используются напрямую (таймзону считает
  движок натальной карты) — можно удалить при чистке.
- Rate-limit / антифрод на вызовы OpenAI — нет. Для публичного запуска нужен
  (иначе аноним может жечь токены через `/api/day`, `/api/reading`).
