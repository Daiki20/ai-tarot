# Натальная карта

## Общая картина

После регистрации пользователь обязан заполнить натальную карту (`/onboarding/natal`).
Карта считается один раз, хранится в БД (`natal_charts`), показывается в профиле
и **подмешивается во все AI-разборы** этого пользователя.

## Что спрашиваем (форма `NatalForm`, `src/components/NatalForm.tsx`)

| Поле | Зачем |
| --- | --- |
| Имя | обращение, подпись карты |
| Пол (необязательно) | лёгкий контекст |
| Дата рождения | знаки планет |
| Время рождения (+ чекбокс «не знаю точное время») | Асцендент, MC, дома |
| Город рождения | координаты и часовой пояс |

Кнопка «Проверить» дёргает `POST /api/natal/geocode` и показывает распознанный город
и координаты. Без времени рождения карта строится без домов, Асцендента и MC
(положение Луны — приблизительное).

## Как считается (`src/lib/natal/compute.ts`)

Обёртка над **`circular-natal-horoscope-js`** (npm, чистый JS, без сети):
- тропический зодиак, система домов **Placidus**;
- историческая таймзона по координатам — внутри библиотеки (своя база tz);
- своя эфемерида (точность «знак + градус + дом + мажорные аспекты» — достаточно
  для интерпретации; для эфемеридной точности уровня Swiss Ephemeris — отдельная задача).

`computeNatalChart(input)` возвращает `{ chart, summary, timezone }`.

### Что в `chart` (jsonb в БД)

- **`placements`** — 10 планет + Хирон: `key`, `label`, `sign`/`signKey`,
  `lon` (абс. эклиптическая долгота 0–360, нужна для колеса), `degree`/`degreeText`,
  `house`, `retrograde`, `dignity`/`dignityLabel`.
- **`nodes`** — Восходящий/Нисходящий узел, Лилит.
- **`ascendant`, `midheaven`** — `{ sign, signKey, degreeText, lon }` (или `null`).
- **`houseCusps`** — 12 абс. долгот куспидов (или `[]` без времени).
- **`houses`** — те же куспиды в человекочитаемом виде.
- **`aspects`** — мажорные (соединение/секстиль/квадрат/трин/оппозиция) между
  планетами: `a`/`b`/`aKey`/`bKey`, `type`/`typeKey`, `orb`. Отсортированы по орбу.
- **`chartRuler`** — управитель знака Асцендента (традиционные управители) и где он стоит.
- **`lunarPhase`** — фаза Луны при рождении (8 фаз, из угла Солнце→Луна).
- **`stelliums`** — 3+ планеты в одном знаке.
- **`hemispheres`** — акцент по полусферам (верх/низ, восток/запад) по домам.
- **`balance`** — стихии и кресты: в штуках и **во взвешенных %**
  (веса: Солнце/Луна/ASC ×3, личные планеты ×2, социальные и высшие ×1).
- **`meta`** — имя, пол, дата/время, координаты, таймзона, система, движок.

### Достоинства (`dignity`)

Обитель / экзальтация / изгнание / падение — по фиксированной таблице для 7
классических планет (Солнце…Сатурн). Таблицы `DIGNITIES`, `RULER_OF` в `compute.ts`.

### Эфемеридная проверка

Значения сверялись с реальными эфемеридами (декабрь 1993, июнь 1995) — сходятся
на уровне градуса и мажорных аспектов.

## Геокодер (`src/lib/natal/geocode.ts`)

`geocodeCity(query)` → `{ label, lat, lon } | null`. Сейчас **OpenStreetMap Nominatim**
(бесплатно, без ключа, `User-Agent` обязателен). Замена — без изменения контракта.
Подробнее — [EXTERNAL-SERVICES.md](./EXTERNAL-SERVICES.md).

## Отрисовка (профиль)

| Компонент | Что рисует |
| --- | --- |
| `src/components/NatalWheel.tsx` | SVG-колесо: кольцо знаков с глифами и границами, градусные тики, дома Placidus, оси AC–DC / MC–IC, планеты с тиками на истинный градус, линии аспектов (золото — гармоничные, роза — напряжённые), `℞` у ретроградных. Считается на сервере, детерминировано. |
| `src/components/AspectGrid.tsx` | Треугольная сетка аспектов между 10 планетами. |
| `src/components/NatalChartView.tsx` | Всё вместе: колесо + таблица планет с достоинствами + углы/управитель/фаза Луны + узлы + стеллиумы + полусферы + бары стихий/крестов в % + куспиды домов + список аспектов. |

Колесо строится от **Асцендента слева** (9 часов), зодиак и дома — против часовой.
«Перекос» размеров домов и «не Овен наверху» — норма для Placidus (особенно на
северных широтах), не баг.

## Как влияет на расклады

`src/lib/natal/context.ts` → `getNatalContext()`:
- берёт `natal_charts.summary` текущего пользователя **по куке сессии** (не из тела
  запроса — не подделать);
- best-effort: гость или упавшая БД → `null`, разбор идёт без натального блока.

Все AI-роуты (`/api/reading`, `/api/chat`, `/api/matrix`, `/api/day`) зовут её и
передают строку в `build*Messages`, где `natalSystemBlock()` (`src/lib/natal/prompt.ts`)
добавляет её отдельным `system`-сообщением.

**Эффект:** два человека на одни и те же карты и вопрос получают разный по акценту
разбор — под темперамент, сильные зоны, слепые пятна и врождённые сценарии.
**Не влияет** на то, какие карты выпадут (тасовка равновероятная). Не превращается
в гороскоп — ИИ инструктирован вплетать выводы простым языком.

## Совместимость старого формата

Карты, сохранённые до расширения расчёта, **самовосстанавливаются**: при заходе в
`/profile` проверяется формат `chart`; если старый — пересчитывается из сохранённых
данных рождения и перезаписывается (`src/app/profile/page.tsx`). Компоненты вдобавок
имеют мягкие дефолты.
